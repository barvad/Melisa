## 4. Структура хранения

### 4.1 Таблица Chunks

```sql
CREATE TABLE public."Chunks" (
    "Id" int4 GENERATED BY DEFAULT AS IDENTITY 
        (INCREMENT BY 1 MINVALUE 1 MAXVALUE 2147483647 START 1 CACHE 1 NO CYCLE) NOT NULL,
    "Embedding" public.vector NULL,
    "Url" text NOT NULL,
    "Text" text NOT NULL,
    CONSTRAINT "PK_Chunks" PRIMARY KEY ("Id")
);

CREATE INDEX "IX_Chunks_Embedding" ON public."Chunks" 
    USING hnsw ("Embedding" vector_cosine_ops);
```

### 4.2 Описание полей

| Поле | Тип | Описание |
|------|-----|----------|
| Id | int4 | Первичный ключ (автоинкремент) |
| Embedding | vector(512) | Векторное представление чанка |
| Url | text | Ссылка на оригинальную статью Star Wars Wiki |
| Text | text | Текст чанка (содержимое статьи) |

### 4.3 Индексы
- **Первичный ключ:** PK_Chunks (Id)
- **Векторный индекс:** IX_Chunks_Embedding (HNSW, cosine similarity)

## 5. Процесс индексации

### 5.1 Метод API
```
Endpoint: POST /IndexAll
Сервис: Practicum.MelisaBot
```

### 5.2 Исходные данные

| Параметр | Значение |
|----------|----------|
| **Wiki-API** | https://starwars.fandom.com/ru/api.php |
| **Количество документов** | 3 668 |
| **Источник** | Star Wars Fandom Wiki |
| **Формат документов** | Очищенные тексты статей |
| **Способ загрузки** | Последовательный (без параллелизации) |

### 5.3 Чанкование документов

**Параметры разделения:**
- **Библиотека:** Microsoft.ML.Tokenizers / Tokenizers.DotNet
- **Метод:** RecursiveCharacterTextSplitter
- **Размер чанка:** 500-1000 токенов
- **Перекрытие:** 50 токенов

**Результат чанкования:**

| Параметр | Значение |
|----------|----------|
| **Всего чанков** | 14 866 |
| **Среднее число чанков на документ** | ~4.05 |
| **Минимальная длина чанка** | 150 токенов |
| **Максимальная длина чанка** | 1 050 токенов |

### 5.4 Генерация эмбеддингов

**Процесс:**
1. Загрузка ONNX-модели Xenova/distiluse-base-multilingual-cased-v2 через Microsoft.ML.OnnxRuntime
2. Для каждого чанка:
   - Токенизация через Microsoft.ML.Tokenizers
   - Инференс модели
   - Получение вектора размерности 512
   - Сохранение в поле Embedding таблицы Chunks

**Особенности реализации:**
- Модель запускается локально через ONNX Runtime
- Все вычисления на CPU
- Векторы сохраняются в формате pgvector

### 5.5 Временные затраты

| Этап | Время |
|------|------|
| Загрузка 3 668 документов через Star Wars Wiki API | ~1 час 30 минут |
| Очистка и чанкование (Microsoft.ML.Tokenizers) | ~15 минут |
| Генерация эмбеддингов через ONNX Runtime (14 866 чанков) | ~45 минут |
| Сохранение в PostgreSQL через Entity Framework Core | ~10 минут |
| Построение HNSW индекса | ~8 минут |
| **Общее время выполнения IndexAll** | **~2 часа 48 минут** |

**Примечание по производительности:**
> Индексация выполнялась последовательно из-за риска возможных ограничений Star Wars Wiki API (rate limiting). В production-окружении с собственным Wiki-сервисом возможна параллельная обработка через Task Parallel Library (TPL), что сократит время до 20-30 минут.

## 9. Заключение

Созданный векторный индекс на базе pgvector с моделью Xenova/distiluse-base-multilingual-cased-v2 (ONNX) обеспечивает:

- **Полное покрытие** всех 3 668 статей Star Wars Fandom Wiki (14 866 чанков)
- **Высокую скорость поиска** (25-40 ms) благодаря индексу HNSW
- **Релевантные результаты** по тестовым запросам (пример с кораблями)
- **Интеграцию с C# стеком** через Microsoft.ML.OnnxRuntime и Pgvector.EntityFrameworkCore
